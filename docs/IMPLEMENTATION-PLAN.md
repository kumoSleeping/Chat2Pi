# Chat2Pi 0.4 实施计划与验收

1. 每个配置绑定一个账号和一台电脑；云端与本地使用相同的绑定字段，执行密钥和本地权限单独保存。
2. 用 Durable Object 保存账号和绑定；首次凭初始化密钥创建管理员，以后通过管理接口动态添加账号与电脑。
3. ChatGPT 只增加 `manage` 一个管理工具；HTTPS API 和 CLI 复用相同的鉴权与授权逻辑，支持外部智能体。另提供 `/api/call` 与 `call` 命令，以同一账号凭证直接调用电脑工具。
4. OAuth 身份、设备连接及每次执行均校验账号；停用账号、撤销设备与轮换凭证及时生效，保护最后一名管理员。
5. 凭证通过五分钟一次性领取链接交付；敏感管理操作采用两步确认。
6. 提供 GitHub 安装方式、Windows 接入说明和自行部署配置；不限制 Pi 版本。
7. 先完成本地隔离与 OAuth 测试，再部署域名、迁移本机代理，最后验证真实 MCP 调用和 ChatGPT 界面连接。

已验证：六项本地执行测试；云端运行时中的账号隔离、同名设备隔离、在线离线状态、管理员权限与撤销测试；正式域名 OAuth 登录、九项工具目录、管理员身份、真实本机读取及令牌刷新。

Windows 接入提供配置和操作说明，目前没有 Windows 真机测试结果。浏览器插件接入的实际状态以本次交付说明为准。

## 0.5 本机管理

凭证与绑定默认保存在用户目录 `.chat2pi`，账号、绑定、下载和运行记录分别归档。`start / stop / restart / status` 自动读取全部绑定，支持显式 `--all`。管理命令自动选择唯一账号，多账号时要求明确选择。后台服务通过带独立随机凭证的本机控制接口停止，不依赖 shell 进程匹配或按 PID 强行终止。

已验证多绑定启动、重复启动、重启、停止、控制接口拒绝未认证请求，以及配置损坏后仍可停止已有进程。
